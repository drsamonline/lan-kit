**1.1.0 — the two app forks came back into the kit: boards, a PIN, snapshots, and finding a room.**

The kit is the shared core, and two apps had each improved it in their own vendored copy:
`canteen-lan` added an optional room **PIN** and made a bare string sendable as a message;
`chalk-lan` added **boards**, an **onSnapshot** event, `Lan.health`, `Lan.scan`, and a
`hostUrl` that survives `file://`. Kits are one-way (`PROMPTS/retrofit.md`), so both
improvements move INTO the kit and neither app is touched — the kit is now a superset of
both copies, which is what "harvest" means.

- **Host:** `pin`, `app`, board-scoped `broadcast(msg, board)`, `snapshot(board, doc)`,
  `?board=` on the event stream, `app` and `pin: true|false` in `/health`.
- **Client:** `board` and `pin` options, `onSnapshot`, `Lan.health(url)`, `Lan.scan(opts)`,
  and a bare string sent as `{t:"text",text:...}`.
- **The PIN is deleted from the message before it is broadcast.** It rides on every POST,
  so broadcasting it would publish the secret to the room it protects. This is the one
  behaviour here that is a security property rather than a feature, and it has its own
  assertion: `THE PIN IS NOT BROADCAST TO THE ROOM`.
- **`Lan.version` now agrees with `VERSION`.** The file said `0.1.0` while the repository
  said `1.0.0`; a version that disagrees with itself is worse than none.

A client that names no board still receives everything, so no existing app changes
behaviour. 42 assertions (was 8), mutation-tested three ways.

**Not harvested, and named rather than half-done:** `canteen-lan`'s host also keeps a
`journal` on disk, serves the app itself (`appDir`), takes `routes`, and can `mirror` to a
second host; `chalk-lan` has a `test-host.js` harness. Those are the next increment.
